3. Model Context Protocol¶

In the previous sections, we have implemented our tools using Pydantic AI’s @agent.tool_plain decorator. Wrapping Python functions as tools using the harness framework is straightforward, but comes with limitations. Suppose you are very happy with your get_current_datetime tool, and would like to reuse it in another agent or share it with other people in your company. To do this, you would need to either import or simply copy the function from your existing code. This further requires that you can edit the other agent’s source code and that the agent is written in the same language as the tools.

The Model Context Protocol standard was developed to enable harnesses (hosts in MCP terminology) to access external resources provided by an MCP server. The MCP host uses an MCP client to communicate with the server. This means that the harness only needs to implement an MCP client to integrate with servers that can be deployed locally or remotely in a variety of programming languages. This is especially useful if you are using a pre-existing harness, such as a coding agent like Claude Code or Codex. These typically provide an MCP client through which you can provide them with custom tools.

In the tabs below, you can compare implementing a tool directly in our agent, as you did in the previous sections, with implementing it via an MCP server. The only changes are to initialize a new MCP server with mcp = MCPServer("Demo") (named Demo in this case) and to change the decorator to @mcp.tool().

from pydantic_ai import Agent

agent = Agent(model)


@agent.tool_plain
def get_current_datetime(timezone: str | None = None) -> str:
    """Get the current date and time.

    Args:
        timezone: IANA timezone name, e.g. 'Europe/Stockholm'. Omit for the user's local time.
    """
    logfire.info("tool called with {timezone=}", timezone=timezone)
    tz = ZoneInfo(timezone) if timezone else None
    now = datetime.datetime.now(tz).astimezone(tz)
    result = now.strftime("%Y-%m-%d %H:%M:%S %Z (UTC%z)")
    logfire.info("tool result: {result}", result=result)
    return result

from mcp.server import MCPServer

mcp = MCPServer("Demo")


@mcp.tool()
def get_current_datetime(timezone: str | None = None) -> str:
    """Get the current date and time.

    Args:
        timezone: IANA timezone name, e.g. 'Europe/Stockholm'. Omit for the user's local time.
    """
    logfire.info("tool called with {timezone=}", timezone=timezone)
    tz = ZoneInfo(timezone) if timezone else None
    now = datetime.datetime.now(tz).astimezone(tz)
    result = now.strftime("%Y-%m-%d %H:%M:%S %Z (UTC%z)")
    logfire.info("tool result: {result}", result=result)
    return result

As the name says, the MCP server is a server that needs to be started before we can use it. You will do this in Exercise 3.1 with the following command. The streamable-http transport runs the server as an HTTP service that clients connect to over the network.

uv run mcp run 03_mcp_server.py --transport streamable-http

This will start the MCP server locally at the address http://127.0.0.1:8000/mcp.

But how do we connect the MCP server to our agent? In the code snippet below, we add a new MCP capability to the agent. This is all that is needed: the agent will now be able to use the tools of the MCP server.

agent = Agent(
    model,
    capabilities=[MCP(url=f"http://127.0.0.1:{os.getenv('MCP_PORT', '8000')}/mcp")],
)

Exercise 3.1¶

Exercise

Before modifying the MCP server, let’s see how the existing get_current_datetime tool works. Start the MCP server in a new terminal from the hands-on directory:

uv run mcp run 03_mcp_server.py --transport streamable-http

You can try opening http://127.0.0.1:8000/mcp in your browser. Do not worry if it gives you some message about a missing session id. The server works, but the request needs to contain more information than what your browser sends. You should also see some message in the terminal where you started the server.

Leave it running, and in a second terminal start the agent from the hands-on directory (it reads your token from .env, as in the previous episodes):

uv run 03_mcp_client.py

Ask the agent something like “What time is it?” and look at the log of the terminal where your agent is running. How many times is the MCP server called, and when does the LLM come into play?

Solution

You likely saw the following steps. This is what they mean:

  1. agent run: your prompt starts an agent run in the harness.

  2. server/discover: the harness asks the MCP server for its supported protocol versions, capabilities and identity.

  3. tools/list: the harness fetches the server’s tools through MCPToolset.

  4. First chat: the LLM gets your question and the tool definitions, and responds with a call to get_current_datetime. The inference server parses the tool call from the LLM’s output and returns it to the harness as a structured response.

  5. running tool → tools/call → MCP send: the harness calls the tool on the MCP server.

  6. Second chat: the LLM gets the tool result (plus the tool definitions again) and writes the answer.

The MCP server is called three times (discover, list, call), and the LLM twice.

The key point: the LLM never interacts with the MCP server directly. The harness coordinates everything. Before the LLM is called for the first time, the harness has already fetched the server’s tools and added them to the LLM’s context together with your prompt.

Exercise 3.2¶

Exercise

In this exercise, start expanding the MCP server given in hands-on/03_mcp_server.py to add your own tool.

Add a tool book_flight to 03_mcp_server.py that takes a flight number (flight_no, as in data/flights.csv), a passenger name and a date, and appends the booking as a new row to data/bookings.csv using pandas.

Some hints to help you get started:

  • Have a look at the search_flights tool for the decorator and docstring.

  • The docstring and type hints become the tool description that is added to the context of the LLM.

  • pd.DataFrame.to_csv can append with mode="a". Only write the header if the file doesn’t exist yet.

You can test it as follows:

  1. Restart the MCP server. It doesn’t pick up code changes automatically.

  2. Start the agent and ask: “Book a flight from Helsinki to Stockholm next Monday for Linus Torvalds.”

  3. Check the log: which tools does the agent call, and in what order?

  4. Check the file: cat data/bookings.csv

Think about the following:

  • Ask “Book me a flight to Stockholm tomorrow” without giving a name. Does the agent ask for it, or make one up?

  • This tool might have more consequences than the search flights tool. Should the agent ask for confirmation before booking?

Solution

@mcp.tool()
def book_flight(flight_no: str, passenger_name: str, date: str) -> str:
    """Book a flight for a passenger.

    Args:
        flight_no: flight number from search_flights, e.g. 'AY100'.
        passenger_name: full name of the passenger.
        date: travel date 'YYYY-MM-DD'.
    """
    bookings_csv = Path(__file__).parent / "data" / "bookings.csv"
    booking = pd.DataFrame([{"flight_no": flight_no, "passenger_name": passenger_name, "date": date}])
    booking.to_csv(bookings_csv, mode="a", header=not bookings_csv.exists(), index=False)
    return f"Booked flight {flight_no} on {date} for {passenger_name}."

You can also try out an MCP server with the model solution by stopping the old MCP server and starting a new one with the following command:

uv run mcp run 03_mcp_server_solution.py --transport streamable-http

Going further (optional)

  • Return an error if the flight doesn’t exist in flights.csv or doesn’t fly on that date.

  • Add a list_bookings tool that shows the bookings for a passenger.

  • Add a cancel_booking tool.

  • Connect your MCP server to another harness you use, for example a coding agent or your IDE. Look up how it registers MCP servers, point it at http://127.0.0.1:8000/mcp and ask it something only your tools can answer. The same server now works in a harness you did not write.

Using existing MCP servers¶

You don’t have to write every MCP server yourself. Many services already provide one, and connecting to it works the same way as connecting to your own server. For example, the LUMI AI Factory runs a public MCP server at https://lumi-aif-agents.2.rahtiapp.fi/mcp. Its tools search the LUMI documentation and report the status of LUMI services. To give our agent access to it, add a second MCP capability:

agent = Agent(
    model,
    capabilities=[
        MCP(url="http://127.0.0.1:8000/mcp"),
        MCP(url="https://lumi-aif-agents.2.rahtiapp.fi/mcp"),
    ],
)

Only connect to MCP servers you trust. The tool descriptions a server returns go straight into the LLM’s context, so a malicious server can try to steer your agent, and its tools can do whatever the server’s code does. More on security in the security section.
